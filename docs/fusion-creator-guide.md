# Руководство Fusion Creator v1

**Fusion Creator v1** встроен в единый `fusion-launcher` и разделён на последовательные этапы **Основа → Состав → Профили → Проверка → Выпуск** поверх общих типов `ProgramDescriptor` `1.0`, `GameManifest` `1.1`, `FusionService` и `PackerEngine`.

## Рабочий цикл автора

1. **Основа (`Base`):**
   - Выбор или создание проекта `1.1`, привязка локальных каталогов управляемых компонентов и файла ключа подписи Ed25519 PKCS#8 PEM (`fusion_creator_private_bindings_save`).
   - Приватный ключ подписи никогда не входит в экспорт и хранится локально по указанному пользователем пути; перед публикацией сделай резервную копию PEM-файла вне рабочих каталогов сборки.
   - Сборка подписанного выпуска (`fusion_creator_build`): потоковая нормализация и упаковка ZIP, расчёт BLAKE3 манифеста и инвентаря, выпуск с переносимыми Source-relative ссылками `artifacts/<blake3>.zip`.

2. **Проверка (`Verification`):**
   - Для выбранного выпуска текущей ревизии выполняются раздельные проверки по совместимым парам `(buildProfileId, controlsProfileId)`:
     - `structure_integrity` — независимая проверка подписи, манифеста, инвентаря и ZIP по сохранённым байтам без обращения к исходной папке автора и ключу подписи;
     - `clean_install` — чистая установка через `FusionService` во временную изолированную библиотеку с проверкой активного snapshot, выбранных слоёв и фактических rendered конфигов (`.ini` / `.xml`).
   - Статусы `Ввод проверен` (`creator-verify-result-input`), `observed_launch`, `manual_scenario` и `https_acquisition` отображаются отдельными строками и никогда не объединяются со статусом `structure_integrity` или `clean_install`.
   - Если проект объявляет `entrypoint.environment_paths`, безъядерная чистая проверка в Creator блокируется явной диагностикой до локального host-одобрения с привязкой к exact BLAKE3 `ProgramDescriptor` и набору имён переменных.

3. **Выпуск (`Release` — Экспорт и проверка HTTPS):**
   - **Export Gate:** кнопка `Export` открывается только после прохождения `structure_integrity` и `clean_install` по **всем** объявленным совместимым парам профилей выбранного выпуска.
   - Экспорт пишет в выбранную пустую папку строго allowlist-файлы (`source-index.json`, `manifests/<game>-<blake3>.json`, `manifests/<game>-<blake3>.artifacts.json`, `artifacts/...`) атомарно, без приватных путей автора, ключей, `deviceId`/GUID и пользовательских сохранений.
   - Старые выпуски со ссылками `https://offline.fusion.invalid/...` остаются пригодными для локального `Verify`, но не переписываются при экспорте — для публикации по HTTPS собери новый выпуск.
   - После размещения экспортированной папки на HTTPS-хостинге `Verify HTTPS` (`fusion_creator_verify_https`) выполняет полную потоковую загрузку `artifacts/...` с пустым кешем и сверяет полученные байты с pinned хешами выпуска.

## Профиль управления игрока, `eden_param_package_v1` и SDL-барьер

- В окне деталей игры `1.1` игрок выбирает пару `Профиль сборки` и `Профиль управления`.
- Для профилей `eden_param_package_v1` с устройством `sdl_gamecontroller` игрок открывает встроенный диалог выбора/проверки и назначения контроллера (`CreatorDeviceDialog`), настраивает кнопки/стики/мёртвые зоны осей и сохраняет локальную привязку (`fusion_input_bindings_save`). Физические `GUID`, `port`, `sdl_mapping` и калибровка сохраняются только локально в `fusion-input-private`.
- Перед запуском процесса `ProcessSupervisor` (через `InputService::with_released_for_launch`) закрывает SDL-хендлы, проверяет `handlesClosed` и `SDL_WasInit(0) == 0`, удерживает процесс-глобальный SDL-lease во время запуска и запрещает спавн при отсутствии подтверждения. После выхода дочернего процесса возможен повторный `devices()` / старт новой сессии.

## Область автоматических и непройденных проверок (`NOT TESTED`)

Автоматические наборы `cargo test`, `npm run check`, `npm run mvp:visual`, `runtime_sdl_tests`, `universal_portable_tests`, `stage5-cross-volume` и изолированный нативный desktop E2E-сценарий доказывают работу в изолированных тестовых контурах. Не пройдены на реальном внешнем железе/артефактах и требуют отдельной ручной проверки владельца:

- **Физический SDL-геймпад** (`NOT TESTED` — на сборочной машине не подключён физический контроллер; проверен только виртуальный SDL-fixture и барьер освобождения handles): подключаешь геймпад → Settings / Creator → «Проверить устройство ввода» → старт сессии, проверка кнопок/стиков, назначение/мёртвые зоны, сохранение, запуск Eden с применением `ParamPackage` и повторное обнаружение после выхода.
- **Реальный бинарник Eden `0.2.1`** и пользовательский игровой дамп / TOTK (`NOT TESTED` — проприетарные/внешние пользовательские файлы на машине не подключались и не проверялись).

## Intended Visual Diffs

- Все новые элементы этапа Stage 4–5 UI (`CreatorVerifyPanel`, `CreatorDeviceDialog`, `CreatorReleasePanel`, `FusionGameDetailsModal`) переиспользуют существующие CSS-токены и классы (`--rh-*`, `fusion-*`, `rh-filter-chip`, `rh-focusable`, `rh-library-sort`, `rh-mini-action`).
- **Визуальные изменения:** добавлены поле ввода пути экспорта `creator-export-path` в `CreatorReleasePanel`, отдельная строка статуса `creator-verify-result-input` в результатах проверки `CreatorVerifyPanel`, контролы профилей/назначения SDL-кнопок и калибровки внутри активной сессии `AssignmentDialog`, а также селекторы `fusion-build-profile` / `fusion-controls-profile` и кнопка настройки контроллера в `FusionGameDetailsModal`.
- Новые глобальные визуальные роли, палитры и авто-утверждение screenshot baselines не добавлялись; `npm run mvp:visual` проходит во всех поддерживаемых разрешениях (`1280×720`, `1365×768`, `1440×900`, `1920×1080`, `en`/`ru`).
